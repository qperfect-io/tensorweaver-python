    API Reference¶

    An index of the public surface. For what the knobs mean see Concepts, for execute()'s keywords see Circuit Execution, and for runnable code see Examples.

    Gate and operator matrix inputs

    Anything taking a one- or two-qubit gate or operator (apply_gate_1q, apply_gate_2q, expectation_1q, expectation_2q, apply_kraus_*) accepts a numpy array of dtype complex128: (2, 2) for a 1Q gate, (4, 4) for a 2Q gate, (n_ops, dim, dim) for a stack of Kraus operators. On a qudit site of dimension d, the shapes are (d, d) and (d₁·d₂, d₁·d₂).

    A flat list of floats in column-major [re, im, re, im, ...] order is also accepted, with length 8 for a 1Q gate and 32 for a 2Q gate. It is deprecated; use numpy arrays.

    Bitstring / qubit ordering

    TensorWeaver is little-endian by qubit index: bitstring position i is qubit i. This is the opposite of Qiskit's convention, so bitstrings from mps.sample_bitstring(), mps.sample(), results.cstates, and results.histogram() appear reversed compared to Qiskit output. The same applies to the bitstring argument of mps.amplitude().

    High-level¶

    execute¶

    Every keyword, with its default and when to change it, is documented in Circuit Execution.

    tensorweaver.execute(circuit, nsamples=..., *, num_qubits=..., bonddim=..., entdim=..., max_bond_dim=..., sv_cutoff=..., algorithm=..., post_compress=..., strict_bonddim=..., seed=..., bitstrings=..., reorderqubits=..., fuse=..., fuse_threshold=..., canonicaldecompose=..., simplify=..., buffer=..., traversal=..., linalg=..., usegpu=..., usemkl=...) ¶

    TwSimulator¶

    A reusable simulator. Configuration is fixed at construction; nsamples, seed, and num_qubits are per call.

    Bases: LocalBackend

    MPS quantum circuit simulator, backed by the TensorWeaver core.

    Subclasses :class:mimiqcircuits.backends.LocalBackend, so the usual sim.execute(circuit, nsamples=..., seed=...) call works and returns a :class:mimiqcircuits.QCSResults. :meth:capabilities lists what it can serve.

    Every knob below is set on the constructor and fixed for the life of the instance; build a new simulator to change one. Accepting them per call as well would mean distinguishing "not passed" from "passed the default" on every keyword.

    Execution mode. The circuit decides, not a keyword. Trailing measurements are split off into a classical projection and do not count. If everything left is unitary, the state is evolved once and nsamples bitstrings are drawn from it (sampling mode, one entry in results.fidelities). If any surviving operation on qubits is non-unitary (a mid-circuit Measure or Reset, a noise channel, qubit loss), the circuit is re-evolved from scratch nsamples times (trajectory mode, one fidelity and one cstate per trajectory).

    Parameters:

    Name Type Description Default
    bonddim int

    Maximum MPS bond dimension, the memory and accuracy knob. Default 256. Raising it lets the state carry more entanglement before truncation, at a cost that grows steeply; lowering it truncates earlier and lowers the reported fidelity.

    		 256
    entdim int

    Maximum bond dimension of the MPO that gates are fused into between state updates. Default 16. Larger values batch more gates per update. A gate whose operator rank exceeds entdim raises rather than being applied at reduced accuracy, so raise entdim if a circuit reports that.

    		 16
    sv_cutoff float | None

    Singular-value floor applied when an MPO is compressed into the state. None (default) uses the library default 1e-7. Lower it toward machine precision for accuracy, raise it for speed.

    		 None
    mpo_cutoff float | None

    Singular-value floor applied while gates are fused into the MPO. None (default) uses the library default 1e-15, which is essentially exact. Independent of sv_cutoff; there is rarely a reason to change it.

    		 None
    algorithm Algorithm

    How each fused MPO is applied to the state. The names read as the method plus what it applies: "dmpo" is direct MPO application, "cmpo" canonical, and "vmpoa" / "vmpob" variational variants a and b. "vmpoa" (default) and "vmpob" run single- and two-site variational sweeps seeded by a zip-up. The default matches MPSSim's (MPO1z), so results are comparable with the incumbent MIMIQ engine without tuning. "dmpo" is the zip-up alone, the cheapest per application.

    "cmpo" is a single pass like "dmpo", arranged so the weight it discards is chosen against the state's own Schmidt spectrum. Where the ceiling binds it keeps more of the state and tends to leave it narrower, which makes later gates cheaper too, at close to single-pass cost. It is also the accurate choice under usegpu=True. See the "Choosing an algorithm" page of the manual for how to decide.

    		 'vmpoa'
    strict_bonddim bool | None

    Whether every intermediate bond must stay within bonddim while an MPO is applied. It never changes the bond dimension of the result, which is at most bonddim either way.

    • None (default): the algorithm's own default, strict for "dmpo", "vmpoa" and "vmpob", relaxed for "cmpo".
    • True, strict: the zip-up ("dmpo", and the seed of the two variational algorithms) cuts its carry to bonddim as it goes, so the memory a run needs follows from bonddim alone. Those cuts are made in a gauge where the singular values are not the state's Schmidt values, so they can drop weight the result did not need to lose. At bonddim < entdim (fused MPOs reach bond dimension entdim) a cut can wipe out the state altogether, so a strict run needs bonddim >= entdim. From there up, "dmpo" suffers most, above all with post_compress=False; the variational sweeps repair most of it. The reported fidelity shows the loss: a strict run is less accurate, not silently wrong.
    • False, relaxed: the zip-up's carry may grow to max(4 * bonddim, D) for an MPO of bond dimension D and is cut to bonddim afterwards, in canonical form. The result is exact whenever it fits under bonddim, and entdim may be anything, at the price of more memory and 1.5 to 4 times the time. For the variational algorithms, it seeds the sweeps from this relaxed zip-up: on 20-qubit random circuits "vmpoa" reached 5 to 15% lower infidelity than strict, and "vmpob" matched strict, at 1.4 to 4 times the time.

    "cmpo" has no strict form, so algorithm="cmpo" with strict_bonddim=True raises :class:ValueError here. A run that resolves to strict (True, or None with "dmpo", "vmpoa" or "vmpob") with bonddim < entdim also raises :class:ValueError here, before any circuit runs: raise bonddim to entdim or above, lower entdim, or pass strict_bonddim=False. A value that is neither a bool nor None raises :class:TypeError. Applies on host and device.

    		 None
    post_compress bool

    Run the global recond and compression sweep after every MPO application. Default True. The sweep restores canonical form, which is what keeps the next zip-up's singular values equal to the physical Schmidt weights. Turning it off defers one sweep to end of circuit: faster on circuits that stay well below bonddim, but bond dimension then creeps on zip-up noise until the zipper's intermediate, which carries the MPO bond index and not the state's, crosses bonddim, and truncation in the wrong gauge corrupts the state. Measured on a 16-qubit QFT at bonddim=64: mirror fidelity 1.0 with it on, 0.535 with it off, and the reported fidelity reads 1.0 either way.

    		 True
    seed int | None

    Master RNG seed for every run this instance drives. None (default) draws fresh entropy per run. A seed= on :meth:execute overrides it.

    		 None
    buffer int

    Depth of the gate-fusion pipeline. 0 (default) fuses and applies inline; a positive value runs fusion on a background thread that prepares up to buffer MPOs ahead while evolution applies them, overlapping the fusion of the next block with the application of the current one. Results are identical to buffer=0. The overlap is real parallelism because mps.apply_mpo releases the GIL, and a depth of 2 to 4 is enough because only one or two MPOs are ever in flight.

    		 0
    traversal Traversal

    Order in which gates are walked while they are fused into MPOs. "sequential" (default) is the circuit's insertion order; "bfs" is a breadth-first topological order that groups mutually independent gates into layers; "dfs" is depth-first, following one dependency chain to its end before backtracking. All three produce the same simulated state and differ only in how gates batch into MPOs, which shifts the intermediate bond dimension and therefore the runtime. "bfs" tends to pack each MPO with more commuting gates, which helps on wide, shallow layers.

    		 'sequential'
    linalg Linalg | None

    Linear-algebra library: "openblas", "mkl" or "faer". None (default) takes whichever engine this build ships, preferring OpenBLAS: it is vendored into the wheel, so it works from a plain pip install. Where the wheel has no OpenBLAS engine, which is the Windows wheel, the default resolves to MKL instead. "mkl" is Intel MKL, whose runtime the wheel cannot bundle and must come from the environment; if it is absent, the first use raises :class:ImportError with installation instructions. "faer" is a pure-Rust library with no system dependency, usually slower than the other two. A named engine the build does not have raises at first use rather than switching engine. An unknown name raises :class:ValueError. The resolved value is readable as sim.linalg.

    		 None
    usegpu bool

    Run the state on an NVIDIA GPU. False by default. The whole MPS is moved into device memory once, evolved there, and moved back once, so a circuit pays one transfer at each end rather than one per gate. Requires algorithm="dmpo" or "cmpo", the two single-pass algorithms with a device implementation. The CUDA engine is one module whose host provider is OpenBLAS, so linalg must be unset or "openblas"; any other value raises :class:ValueError. Raises :class:ImportError at first use if this build has no CUDA engine or no GPU is reachable. Prefer "cmpo", the accurate one of the two.

    Whether it is faster depends on the bond dimension. The device wins where the state is large and loses where it is small, because each site's truncated SVD carries a fixed launch cost that the host does not pay. Measured on an A30 against one Xeon core, on a 24-qubit brick-layer circuit: 0.8× at bonddim=64, 2.8× at 128, 8.2× at 256, 24× at 512. So below roughly 64 the GPU is slower, and the case for it grows with the problem. Both paths truncate identically, and the reported fidelities agree to every digit.

    		 False
    max_num_threads int | None

    The most threads a run of this simulator uses, for the linear algebra and for sampling alike. None (default) leaves both to the process setting (see :func:thread_info). The cap is held for the length of each :meth:execute, :meth:evolve, :meth:evolvezerostate and :meth:expectation call and released after, so it never outlives the run. The thread counts are process-wide: simulators running at the same time on different Python threads share them, and each runs at the smallest cap any of them holds. Raises :class:ValueError below 1.

    		 None
    usemkl bool | None

    Deprecated, use linalg. True means linalg="mkl" and False means linalg="openblas". Passing it emits a :class:DeprecationWarning, and passing it with a linalg that names a different engine raises :class:ValueError.

    		 None

    Reordering under traversal applies only to the fusable gates between state-reading or measuring instructions. Measurement, reset, channel, observable (Amplitude / BondDim / SchmidtRank / ExpectationValue), barrier and IfStatement stay put and act as synchronisation points. Within a gate run, two gates are ordered relative to each other only when they share a qubit.

    Which engines a wheel carries depends on the platform, because the compute core binds the CBLAS and LAPACKE interfaces directly and no one provider supplies both everywhere: Linux x86-64 ships OpenBLAS, MKL and faer, macOS arm64 OpenBLAS and faer (MKL is x86-only), Windows x86-64 MKL and faer. faer is pure Rust and binds neither interface. This is why linalg defaults to None rather than to an engine name.

    Each engine is a separate native module, so linalg and usegpu are per instance and simulators on different engines can run side by side in one process. Their objects do not interoperate: an :class:~tensorweaver.MPS, :class:~tensorweaver.MPO, Rng or :class:~tensorweaver.TwState built by one engine cannot be passed to a simulator or method using the other, which raises TypeError. To carry a state across engines, round-trip it through MPS.serialize() and MPS.deserialize(), which copies it.

    Caveats

    • num_qubits= on :meth:execute is a TensorWeaver-specific kwarg (also accepted by :class:quantanium.QuantaniumQCS); :class:mimiqengines.MPSSimulator does not expose it. Code that drives the three simulators with a portable sim.execute(c, nsamples=100, seed=42) shape is unaffected.
    • Amplitudes requested in trajectory mode reflect the last shot's state, not an ensemble average, whenever the circuit contains a mid-circuit measure, reset or IfStatement.
    • RNG resolution priority: a call-site seed= beats the instance seed, which beats fresh entropy from :mod:secrets. The free function tensorweaver.execute(...) defaults to seed=42; this method resolves to a concrete int before forwarding, so the two surfaces never collide.
    • :meth:bind substitutes parameters and re-runs the full compile pipeline; there is no native parametric fast path.
    • :meth:evolve returns (state, TruncationLowerBound) and never promotes to ExactFidelity even when fid == 1.0, because each MPO application is an SVD truncation event whose fidelity is at best a lower bound.

    Examples:

    >>> import mimiqcircuits as mc
>>> from tensorweaver import TwSimulator
>>> sim = TwSimulator(bonddim=64)
>>> c = mc.Circuit()
>>> c.push(mc.GateH(), 0)
...
>>> c.push(mc.GateCX(), 0, 1)
...
>>> c.push(mc.Measure(), [0, 1], [0, 1])
...
>>> results = sim.execute(c, nsamples=100, seed=42)

    usemkl property ¶

    Deprecated: whether this simulator runs on MKL. Use linalg.

    capabilities() ¶

    Capability tokens this simulator can serve.

    A copy, so a caller cannot mutate the class-level set.

    limits() ¶

    Resource limits: the configured bonddim as max_bond_dim.

    topology() ¶

    Connectivity assumed by the MPS evolution: all-to-all.

    Long-range gates cost more bond dimension than neighbouring ones, but no routing or SWAP insertion is required of the caller.

    build_state(nq, nb=0, nz=0, **_) ¶

    Allocate a fresh |0…0⟩ state on nq qubits.

    The MPS is capped at this simulator's bonddim and built on this simulator's engine, so it can only be used with this simulator. nb and nz size the classical-bit and complex registers.

    zerostate(nq, nb=0, nz=0) ¶

    Back-compat alias for :meth:build_state.

    evolvezerostate(circuit, *, seed=None) ¶

    Evolve a fresh zero state through circuit and return it.

    Returns (state, fidelity), the fidelity being a plain float lower bound on the evolved state. This is a single evolution, so a circuit with mid-circuit measurement or noise gives one trajectory, not an ensemble; use :meth:execute for that.

    Seed resolution: call-site seed=, then the instance seed, then fresh cryptographic entropy from :mod:secrets.

    compile(circuit) ¶

    Lower circuit for the MPS evolution loop.

    Populates :attr:CompileMetadata.active_qubits. Decomposition to TensorWeaverBasis and fusion into MPOs happen later, in :meth:evolve. Qubit reordering is not done here: it is a pass, which :meth:execute runs before compiling when asked to (see :meth:reorder_pass).

    default_passes() ¶

    No passes run by default, so a circuit runs as written.

    reorder_pass(method=None, *, seed=None) ¶

    The pass execute(reorderqubits=...) adds.

    A :class:~tensorweaver.TwReorderQubitsPass scored against this simulator's bonddim. method=None, which is what reorderqubits=True asks for, runs the whole search portfolio; a method name pins one search. To set the pass's alpha or margin, build it yourself and pass it through passes=.

    simplify_pass() ¶

    The pass execute(simplify=True) adds.

    A :class:~mimiqcircuits.SimplifyPass running :data:~mimiqcircuits.DEFAULT_SIMPLIFY_PASSES without resynthesize_2q. That pass rewrites every two-qubit block, which reorders the gates and makes the MPS evolution slower even when it saves a CX. To run it anyway, pass a SimplifyPass through passes=.

    expectation(state, op, *qubits) ¶

    Compute ⟨ψ|op|ψ⟩ on state without mutating it.

    Exact, with no sampling involved. Supports 1- and 2-qubit operators and a :class:PauliString of any length. qubits are the 0-based indices op acts on, in the operator's own leg order, and there must be exactly as many as the operator has qubits.

    Raises:

    Type Description
    ValueError

    if the qubit count does not match the operator, or if a dense operator acts on three or more qubits.

    evolve(state, compiled, *, rng=None, callback=None, stopped=None) ¶

    Evolve state under compiled, in place.

    Returns (state, TruncationLowerBound). The product of the per-step fidelities is always wrapped as :class:TruncationLowerBound, never collapsed to :class:ExactFidelity even at fid == 1.0, because that scalar bounds the fidelity from below rather than claiming the exact state was reproduced.

    Raises:

    Type Description
    TypeError

    if compiled is not a :class:CompiledCircuit.

    apply_segment(state, insts, *, rng=None) ¶

    Fuse a run of loss-free instructions into MPOs and apply it.

    Returns the truncation fidelity of the run. Every qubit in the run is present, so fusing it cannot bury an operation a fired loss should have dropped. The run is padded to the register width, so one that misses the high qubits still builds full-width MPOs.

    apply_instruction(state, inst, *, rng=None) ¶

    Apply a single instruction the driver issues around a loss boundary.

    These are a reload Reset, a Check or MeasureCheck SetBit, or a partial-loss rewrite. A multi-qubit gate has to be fused into an MPO, so it is routed through :meth:apply_segment; everything else applies directly to the MPS.

    sample_kraus(state, channel, targets, *, rng=None) ¶

    Sample one branch of a Kraus channel against the live state and apply it.

    Returns (fidelity, fired_operator). The operator returned is the original one, not a reconstruction, so a LossyOperator branch reaches the driver with its tag intact.

    execute(circuit, *, nsamples=1000, seed=None, rng=None, num_qubits=None, passes=None, fuse=None, fuse_threshold=None, canonicaldecompose=None, reorderqubits=None, remove_swaps=None, simplify=None, reorderqubits_seed=None, callback=None, param_grid=None, strict_pass_order=True, stopped=None, progress=False) ¶

    Execute circuit and return :class:QCSResults.

    The TensorWeaver configuration (bonddim, entdim, sv_cutoff, mpo_cutoff, algorithm, strict_bonddim, post_compress, buffer, traversal, linalg, usegpu) comes from the constructor, not from this call. Circuit preparation, qubit reordering included, comes from this call. Amplitudes and expectation values are requested by putting :class:Amplitude and :class:ExpectationValue operations in the circuit; they write into results.zstates.

    Whether the run is a single evolution plus nsamples draws, or nsamples independent trajectories, follows from the circuit; see the class docstring.

    passes PassPipeline | None

    fuse bool | None

    		 None
    fuse_threshold int | None

    		 None
    canonicaldecompose bool | None

    		 None
    remove_swaps bool | None

    Server-side only: raises when set locally.

    		 None
    simplify bool | None

    		 None
    reorderqubits_seed int | None

    Seed for the layout search alone. None (default) draws it from the run's RNG. On its own it does not ask for reordering.

    		 None
    callback object | None

    Called as callback(applied, total) as the evolution progresses. total is None because MPOs are fused lazily and the count is not known up front.

    		 None
    param_grid list[dict] | None

    List of parameter dicts. Each is substituted into the circuit and executed with its own derived seed, and the return value becomes a list of results, one per grid point. A SweepExperiment does the same and checks that its table binds every free symbol of the circuit; pass one or the other.

    		 None
    strict_pass_order bool

    Enforce the pass pipeline's declared ordering constraints. Default True.

    		 True
    stopped object | None

    Cooperative cancellation handle checked during evolution.

    		 None
    progress bool

    Show a progress display. Default False.

    		 False

    TwDirectSimulator¶

    A simulator that applies a circuit one operation at a time and builds no MPO. Distant qubits are swapped next to each other and stay where they were moved; every read-out answers in your qubit numbering.

    Bases: TwSimulator

    MPS simulator that applies a circuit one operation at a time.

    Where :class:~tensorweaver.TwSimulator fuses gates into matrix product operators and applies each one in a sweep, this simulator builds no MPO. Each gate updates the state directly:

    • a one-qubit gate acts on the site of its qubit;
    • a two-qubit gate acts on two neighbouring sites, contracted together and split back with one truncated SVD. Qubits that are not neighbours are first brought together with swaps of adjacent sites. Which of the two moves is routing's choice: by default the one that leaves the next gates closer, where its swaps cannot truncate, and otherwise the gate's second qubit, next to its first (for a CX, the target to the control);
    • a gate on three to max_gate_qubits qubits gathers them into one block of sites and acts there in one step. A larger gate is decomposed.

    Qubits move and stay moved. Routing swaps are not undone. The state keeps track of where each qubit sits, so a second gate on the same pair needs no routing, and every read-out (sampling, measurement, amplitudes, expectation values) answers in your qubit numbering. :meth:evolvezerostate sorts the chain back at the end and returns the plain MPS, with qubit i on site i. :meth:execute skips that sort, since nothing it reads needs it.

    Fidelity. Every swap is a truncated SVD at sv_cutoff and bonddim, like a gate, and what it discards is in the reported fidelity.

    Not supported. BondDim, SchmidtRank and VonNeumannEntropy read a bond of the chain, and the chain is in whatever order routing left it, so circuits containing them are refused, as are noise channels on three or more qubits. There is no GPU path.

    Which to use. This simulator pays one SVD per two-qubit gate, plus the routing swaps. :class:~tensorweaver.TwSimulator pays one sweep per fused block of gates. Circuits of local gates, or with few gates per qubit between read-outs, favour this one; deep, dense circuits at large bonddim favour MPO fusion.

    Parameters:

    Name Type Description Default
    bonddim int

    Maximum MPS bond dimension. Default 256.

    		 256
    sv_cutoff float | None

    Singular values below this are discarded by every gate and swap. None (default) uses the library default, 1e-7.

    		 None
    max_gate_qubits int

    The most qubits a gate may act on before it is decomposed. Default 4.

    		 DEFAULT_MAX_GATE_QUBITS
    routing Routing

    Which qubit a two-qubit gate moves. "lookahead" (default) moves either one: whichever leaves the next 16 two-qubit gates closer, as long as every bond its swaps cross is at most half of bonddim, so that no swap can truncate. Elsewhere it moves the gate's second qubit next to its first. "target" always does that: for a CX, the target to the control. On the MQT Bench u3+cx circuits at 100 qubits the lookahead was 1.1 to 3.6x faster on 11 of 13 inputs, and up to 1.4x slower on the other two (transpiled qft and qftentangled). from tensorweaver import TwDirectSimulator

c.push(mc.GateH(), 0)

# next to qubit 0, and stays there for the next gate.
c.push(mc.GateCX(), 0, 9)
c.push(mc.GateCZ(), 9, 0)

    TensorWeaverBasis¶

    Bases: DecompositionBasis

    Decomposition basis targeting TensorWeaver's native gate set.

    Terminal operations, executed directly by TensorWeaver: - 1Q parametric: GateRX, GateRY, GateRZ, GateU - 1Q identity: GateID, skipped during execution - 2Q optimized: GateCX, GateCZ, GateISWAP - 2Q generic: any 2-qubit unitary gate, fused into an MPO from its matrix - Multi-controlled: Control(n, 1Q-gate), any number of controls - Measurement/reset: Measure, Reset, MeasureReset - Conditional: IfStatement, terminal when its inner operation is - Z-variable ops: Amplitude, BondDim, SchmidtRank, VonNeumannEntropy, ExpectationValue, all of which observe the state without changing it - Classical: AbstractClassical logic (Not, And, Or, Xor, SetBit0/SetBit1) and the z-register arithmetic Add, Multiply, Pow - Noise channels: any krauschannel subclass, Kraus or mixed unitary - Scheduling: Barrier, a gate-fusion boundary with no effect on the state - Annotations: AbstractAnnotation, which carries no simulation semantics

    Anything else is decomposed through the canonical rewrite rule, which delegates to each gate's _decompose(). A gate that neither is terminal nor decomposes raises :class:DecompositionError.

    Example

    CCX stays as Control(2, GateX), dispatched to apply_controlled_gate¶

    TwReorderQubitsPass¶

    The qubit-reordering pass that execute(reorderqubits=...) runs. Build it yourself and pass it through passes= to set its options; see Qubit ordering.

    Bases: AbstractPass

    Reorder qubits to reduce MPS bond-dimension growth.

    An MPS lays the qubits out on a line, so a gate between two distant qubits pushes entanglement through every site between them. This pass relabels the qubits with a permutation π chosen by the native choose_layout (whose result does not depend on the engine).

    Searches minimise the weighted-distance cost Cα(π) = Σ |π(i) − π(j)|^α · w(i, j), which is smooth and cheap to update. What picks between their results is a different cost, one that knows the bond dimension the run will use: per bond, how many truncations happen there times how many bits each one has to discard against it. The circuit's own layout is always a candidate, so a search that finds nothing better leaves it alone. The rewritten circuit is equivalent to the original; the pipeline maps the results back to the user's qubit frame.

    Parameters¶

    method: None (default) runs the whole portfolio and keeps whichever result scores best. A single spelling ("greedy", "sa" / "simulated_annealing", "multilevel", or True for "greedy") pins one search, which is still scored the same way. alpha: Exponent in the distance the search minimises. None (default) sweeps it, since every result is scored afterwards and a pointless exponent simply loses. Only 1.0 has a meaning: there the sum is identically the number of bond truncations the layout causes. seed: Seed for the stochastic searches. None (default) draws one from the pass-context RNG. bonddim: The bond dimension the run will use, which is what makes the cost meaningful. None (default) reads it off the backend in the pass context, falling back to 256 when the context has none. margin: How much better than the circuit's own layout a candidate must score before it is applied. A layout that truncates nothing is applied whatever the margin.

    See also¶

    :class:AbstractQCSs.ReorderQubitsPass, the Julia analogue used by MPSSim.MPSSimulator, which wraps SOptimizer's search.

    spec() ¶

    Report the pass identity "reorder_qubits" and its parameters.

    seed is part of the spec only when one was given explicitly; a seed drawn from the pass context is not, since it belongs to the run rather than to the pass configuration.

    preserves(feature) ¶

    Return True for every feature.

    Relabelling qubits leaves the circuit's properties intact, and the pipeline's composed_perm step maps the output cstate back to the user's qubit frame.

    apply(ctx, circuit) ¶

    Search for a layout and return the relabelled circuit.

    Returns (circuit, PassResult). The result carries the chosen permutation, or None when nothing beat the circuit's own layout, in which case circuit comes back unchanged. Either way the native report lands in :attr:last_report and is logged at INFO; PassResult has nowhere to carry it.

    MockTensorWeaver¶

    MockTensorWeaver and MockTwSimulator are the same class, and MockState is the state it returns. See Without a licence.

    Bases: TwSimulator

    TensorWeaver's LocalBackend interface, with no simulation behind it.

    Same constructor as :class:~tensorweaver.TwSimulator, same execute, same :meth:capabilities, same :meth:limits, same :meth:topology, same refusals.     Deferred compression

    Skipping the per-call compression sweep and running one pass at a quiet point is faster for a batch of two-qubit gates:

    import numpy as np
import tensorweaver as tw

mps = tw.MPS.zero_state(64, max_bond_dim=256)
mpo = tw.MPO.identity(64, max_bond_dim=16)

mpo.apply_cx(0, 1)
mpo.apply_cz(2, 3)
mps.apply_mpo(mpo, post_compress=False)

gate = np.eye(4, dtype=np.complex128)      # any 4x4 unitary
mps.apply_gate_2q(gate, 4, 5)

# One sweep at quiescence: before measuring, reading an observable,
# or at the end of the circuit.
mps.compress()

    Deferring the sweep leaves the state out of canonical form, so a later truncation compares singular values that are no longer the physical Schmidt weights. Batch only gates you know keep the bond dimension well below the cap, and prefer "cmpo" or "vmpoa" if unsure. See canonical form.

    RoutedMPS¶

    The state behind TwDirectSimulator: an MPS whose qubits move along the chain as gates are routed, with the map from each qubit to its site. Every method takes 0-based logical qubits and every read-out answers in that numbering. No method builds an MPO.

    import numpy as np
from tensorweaver import RoutedMPS

state = RoutedMPS.zero_state(6, 32)
h = np.array([[1, 1], [1, -1]], dtype=complex) / np.sqrt(2)
cx = np.eye(4, dtype=complex)[[0, 1, 3, 2]]
state.apply_gate(h, [0])
state.apply_gate(cx, [0, 5])    # qubit 5 is swapped next to qubit 0, and stays
print(state.layout)             # [0, 2, 3, 4, 5, 1]: qubit 5 sits on site 1
mps, fidelity = state.to_mps()  # sort back: qubit i on site i

    Rng¶

    A seeded generator for reproducible measurement and sampling. The same seed always produces the same sequence.

    import tensorweaver as tw

mps = tw.MPS.zero_state(4, max_bond_dim=16)
rng = tw.Rng(seed=42)
bits = mps.sample_bitstring(rng)

    An Rng belongs to the engine that created it and must be used with states from that same engine.

    Plotting¶

    tensorweaver.visualization needs the visualization extra (pip install 'mimiq-tensorweaver[visualization]'); import tensorweaver alone never loads matplotlib. For a guided tour, see Visualization.

    tensorweaver.visualization.plotbonds(state, mimiqstyle=True) ¶

    Plot the bond dimension and the entanglement entropy along the chain.

    The top panel shows the bond dimension χ of every interior bond on a log-2 scale, with max_bond_dim as a dashed line. A bond that has reached that line is drawn red: it holds as many Schmidt values as the simulator allows, so any further weight on that cut was discarded. A state can also fit its cap exactly, a GHZ state at χ = 2 for one, so red marks where truncation can happen; the fidelity of the run and :func:plotschmidt tell how much it cost. Bonds below the line can still be truncated by sv_cutoff. The bottom panel shows the von Neumann entropy of each cut, in nats, which tells how much entanglement the bond carries.

    Parameters:

    Name Type Description Default
    state TwState | MPS

    a :class:TwState, such as the first value returned by :meth:TwSimulator.evolvezerostate, or an :class:MPS.

    		 required
    mimiqstyle bool

    draw with the MIMIQ matplotlib style (default True); False keeps the active style.

    		 True

    Returns:

    Name Type Description
    The Figure

    class:matplotlib.figure.Figure.

    Example::

    import mimiqcircuits as mc
import tensorweaver as tw
from tensorweaver.visualization import plotbonds

# A 12-qubit brickwork of RY rotations and CX bricks.
c = mc.Circuit()
for layer in range(6):
    for q in range(12):
        c.push(mc.GateRY(0.5 + 0.1 * q), q)
    for q in range(layer % 2, 11, 2):
        c.push(mc.GateCX(), q, q + 1)

# χ = 4 is too small for this depth: the middle bonds reach the cap.
state, _ = tw.TwSimulator(bonddim=4, strict_bonddim=False).evolvezerostate(c)
fig = plotbonds(state)
fig.savefig("bonds.png")

    tensorweaver.visualization.plotschmidt(state, bond, mimiqstyle=True) ¶

    Plot the Schmidt spectrum of one bond on a log scale.

    Each bar is a Schmidt weight λᵢ², the probability carried by one Schmidt vector of the cut. A spectrum that is still high where it ends means the bond dimension is cutting off weight that matters; a spectrum that falls off fast means the state is well represented at this bond. Reading the spectrum moves the orthogonality center to bond, which changes no amplitude.

    tensorweaver.visualization.BondWindow ¶

    A window that follows the bond structure of a :class:TwState as it evolves.

    The window shows what :func:plotbonds shows. It is drawn when created and changes only when :meth:update is called: the state is read as it is then, and the picture moves there gradually. Bond dimensions grow on the log-2 axis, bars fade to red as they reach the cap, and the entropies follow. Between two updates the state can be evolved by any number of instructions.

    The window needs an interactive matplotlib backend such as QtAgg or TkAgg, which in turn needs PyQt / PySide or Tk installed. In Jupyter, run %matplotlib qt first. With a non-interactive backend nothing opens and :meth:update redraws the figure in one step. In a script, the window only repaints during :meth:update; end with matplotlib.pyplot.show() to keep it open and responsive.

    Parameters:

    Name Type Description Default
    state TwState | MPS

    the :class:TwState (or :class:MPS) to follow. Reading it moves the orthogonality center, which changes no amplitude.

    		 required
    mimiqstyle bool

    draw with the MIMIQ matplotlib style (default True).

    		 True
    duration float

    default length of an :meth:update animation, in seconds.

    		 1.0

    Example::

    import matplotlib.pyplot as plt
import mimiqcircuits as mc
import tensorweaver as tw
from tensorweaver.visualization import BondWindow

sim = tw.TwSimulator(bonddim=16, strict_bonddim=False)
state = sim.build_state(20)          # |0...0>: every bond at χ = 1
window = BondWindow(state)

layer = mc.Circuit()
for q in range(20):
    layer.push(mc.GateRY(0.7), q)
for q in range(19):
    layer.push(mc.GateCX(), q, q + 1)
step = sim.compile(layer)

for _ in range(6):
    sim.evolve(state, step)          # as many gates as you like...
    window.update()                  # ...then one animation to the new state

plt.show()                           # keep the window open at the end
